# Trabajando con Java y tipos de datos

## Declaración e inicialización de variables

La declaración se compone del tipo + nombre de la variable:

```java
int miVar;
```

Es posible declarar e inicializar en la misma línea:

```java
int p = 10;
```

También es posible hacer declaración múltiple e inicialización:

```java
int a = 5, b = 10;
int p, s, a = 10; // también pueden mezclarse inicializadas y no inicializadas
```

### Identidicadores

Un identificador puede ser **cualquier combinación de letras (case insensitive), números y los caracteres `$` y `_`. Aún sobre esto, existen algunas restricciones:

* No pueden usarse palabras reservadas: new, break, long... técnicamente serían nombres válidos pero son palabras reservadas. Como curiosidad, la expresión *goto* no tiene ninguna funcionalidad en Java pero es una palabra reservada.
* No pueden empezar por un número.

```java
int _1; // OK
char break; // Error
int 3aj; // Error
float car.t; // Error
long goto; // Error
long  gototouch; // OK
```

Java es **case-sensitive** y los identificadores no son una excepción:

```
Las siguientes variables son diferentes entre sí y pueden coexistir:
int theBall;
int theball;
int Theball;
```

### Ámbito de una variable

* Las variables de clase, atributos o campos, son visibles en toda la clase.
* Las variables locales o de método, son solo visibles dentro de ese método.

```java
class MiClase {

    int n;

    public void metodo() {
        int n;
        n = 10; //se refiere a la variable n dentro del método, no la declarada como atributo en la clase
        this.n = 20; // atributo de la clase, referenciado usando this
    }

}
```

* Las variables locales o de método **NO se inicializan por defecto**.
* Los atributos sí se inicializan por defecto, siguiendo las siguientes reglas:
    * Enteros: 0
    * Decimales: 0,0
    * Booleanos: false
    * Tipo char: `'\u0000'`
    * Objetos: null


### Variables primitivas vs objetos

* La variable primitiva contiene directamente el valor.
* La variable de tipo objeto contiene una referencia: una dirección de memoria donde está el objeto.

```java
int n = 200 // n contiene 200
Object obj = new Object() // obj contiene en realidad el valor, por ejemplo, 0x315A, la dirección de memoria donde está el objeto
```

Entender lo anterior es muy importante porque implica que en las asignaciones, en los tipos primitivos copiamos realmente el valor, pero en los objetos lo único que estamos copiando es el puntero y no creando una copia del objeto.

#### Literales

Un literal es cualquier número "hardcoded", como por ejemplo `int a = 342`, donde `342` sería un literal.
No solo los números del sistema decimal pueden ser representados por literales. Java soporta otros tipos:

```java
289 // literal
0435 // octal, al empezar por 0
0xAF05 // hexadecimal
0b10001100 // binario
```

Como curiosidad, puede utilizarse el caracter `_` para facilitar la lectura de los literales

```java
int a = 3_000;
int hex = 0xA7_03;
```

Sin embargo, existen restricciones, y es que el caracter `_` no puede aparecer al inicio, al final, junto al punto decimal, o junto al prefijo en el caso de hexadecimales o binarios. Las siguientes declaraciones son todas incorrectas:

```java
int a = _1000;
int b = 1000_;
double c = 10_.5;
double d = 10._5;
int hex = 0x_A703;
byte n = 0b_1001;
```

Sin embargo, **existe la excepción con el octal**:

```java
int oct = 0_345 // válido aunque el '0' aquí sea un prefijo
```

Por defecto, los literales son `int` y los literales con punto decimal son `double`

```java
int n = 345;
float g = 9.8; // Error, 9.8 es double
long p = 345l; // Añadimos L minúscula para convertir a long
float s = 3.8f; // Añadimos f para convertir a float
```

A la hora de asignar un literal, obtendremos un error de compilación si este se sale del rango del tipo:

```java
byte b = 324; // Error de compilación
```

### Conversiones

Las conversiones pueden ser implícitas o explícitas.

```java
int x = 45;
double n = x; // Java hace una conversión implícita

double r = 4.5f; // Java está haciendo una conversión implícita al asignar
int x = (int) r; // Conversión explícita
```

Todos los tipos primitivos son convertibles entre sí **excepto el tipo boolean**

Las reglas de conversión implícitas son las siguientes:

1. No se puede convertir de numérico a char:

```java
byte b = 5;
char n = b; // Error
```

2. No se puede convertir de decimal a entero:

```java
float r = 3.4f;
long l = r; // Error
```

3. El tipo de destino debe ser de igual tamaño o mayor que el de origen:

```java
long n = 1;
byte b = n; // Error, aunque en este caso concreto el dato quepa en el byte, el tipo long es más grande
```

**Las reglas anteriores son solo para las conversiones implícitas. Las conversiones explícitas son siempre posibles, a excepción del tipo boolean.**

Se puede convertir explícitamente un double en un char. Java simplemente tomará los bytes que quepan en el char y los guardará. Aunque obviamente el resultado sea impredecible, es posible hacerlo. En cuanto a los objetos, **no se puede hacer conversión entre tipos primitivos y objetos, ni implícita ni explícita.**


### Ciclo de vida de los objetos

El constructor es el bloque de código que se ejecuta al crear una instancia de una clase. El constructor se puede sobrecargar y debe tener siempre el nombre de la clase.

```java
Clase1 c = new Clase1();
```

#### Destrucción de objetos

Los objetos son eliminados por el **garbage collector**. Un objeto es elegido para recolección cuando ya no queda ninguna referencia que le apunta. En ese momento, la JVM llama al método `finalize()`, aunque aquí hay que entender un matiz muy importante.

En Java no tenemos control sobre cuándo se destruye un objeto, por eso técnicamente es más correcto hablar de un **objeto que puede ser recolectado por el recolector de basura**, ya que no tenemos la certeza de cuándo ocurrirá la recolección: es la JVM la que decide cuándo ejecutar el *garbage collector*.

Es una confusión común creer que llamando al método `finalize()` borramos el objeto o, al menos, lo marcamos para su recolección. Esto no es así. `finalize()` es un método que puede ser invocado por la JVM cuando un objeto es considerado inaccesible y elegible para finalización, pero su ejecución **no garantiza que el objeto vaya a ser recolectado inmediatamente ni en algún momento concreto**.

Como curiosidad, `finalize()` puede ser llamado **como máximo una vez por objeto**, y también puede ocurrir que no sea llamado nunca, por ejemplo, si la JVM termina antes de ejecutar la finalización.


### Clases envoltorio

Se encuentran en el paquete java.lang y encapsulan tipos primitivos en objetos. Tenemos la clase `Integer`, `Double` o `Boolean` entre otras.

*Como curiosidad, hay varias razones de ser para las clases envoltorio, pero una de las más sencillas e importantes es simplemente que las colecciones no pueden usar tipos primitivos.*

Tienen métodos estáticos para convertir *Strings* en primitivos:

```java
// parse devuelve el primitivo, mientras que valueOf devuelve otro objeto
int p = Integer.parseInt("300");
Integer n = Integer.valueOf("300");
```

#### Autoboxing / unboxing

Es un concepto muy importante y es la capacidad que tiene Java para asignar u obtener directamente el primitivo a partir de una clase envoltorio.

```java
Integer n = 200; // Autoboxing, no es necesario hacer un new Integer();
Double b = 45.7;

int p = n; // Unboxing, no es necesario obtener del valor de n con un método get()

Integer k = 30;
k++; // Unboxing + autoboxing
```

Los objetos de clases envoltorio **son inmutables**. Su contenido no se puede modificar. Lo que está ocurriendo en el siguiente ejemplo es que se está creando un nuevo objeto

```java
Integer num = 200;
num = num + 100;
```

El caso anterior es interesante, repasemos paso por paso lo que está ocurriendo:
1. Java hace autoboxing para guardar el literal en un `Integer`.
2. Hay una suma, Java hace unboxing de `num` para obtener su valor y sumarlo con `100`.
3. Hay un nuevo autoboxing para guardar el resultado. Al hacer esto, se crea un nuevo objeto que ahora es apuntado por `num`. El antiguo objeto al que apuntaba `num` sigue existiendo en alguna parte de la memoria y es ahora elegible para recolección.
